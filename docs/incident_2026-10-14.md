# Incident 2026-10-14: the evening run stopped on a warrant the vendor cannot price

The 22:30 UTC run on 2026-10-14 failed before sizing, in the price extension, on
the SPY holdings warrant line `SKYD/WS`. No orders were sent. This is what
happened, what was changed, and what the next run should do.

Fixed in `efb/prices.py` and `live/extend.py`, with tests; merged to `main` in
`19368f0` (the merge of `378d7bf`). No Render run was triggered, nothing was
written to R2, the database or the broker, and no email was sent.

## Step 1: the cause

### Where the ticker list comes from

`scripts/run_live_daily.py` calls `extend.extend_archives()` and then
`extend.extend_prices()`.

- `extend.extend_archives()` fetches SSGA's SPY daily holdings file with a plain
  `GET` (`efb/spy.fetch_spy_holdings`) and archives it through
  `efb/spy.archive_snapshot`, one append-only file per as-of date, under
  `data/raw/spy_holdings/spy_holdings_<as_of>.parquet`.
- `extend.extend_prices()` builds its ticker list from
  `extend._live_tickers()` → `extend._spy_tickers()`, which reads the newest
  archive file's `ticker` column, unioned with whatever the last stored proposal
  holds.

So the universe is the SPY holdings file the run just fetched. It is not the
frozen model panel and not the store.

### `SKYD/WS` is in the list tonight's run read

The file SSGA serves — `holdings-daily-us-en-spy.xlsx`,
`Last-Modified: Wed, 14 Oct 2026 10:24:30 GMT`, `as_of 13-Oct-2026`, 506 rows —
carries the row exactly as the source has it:

| name | ticker | identifier | sedol | weight | sector | shares_held | local_currency |
|---|---|---|---|---|---|---|---|
| SKYDANCE CORP | `SKYD/WS` | 69932A113 | C0L7213 | 0.0 | `-` | 6658074 | USD |

The same file also carries the equity line for the same issuer
(`SKYDANCE CORP`, ticker `SKYD`, identifier 69932A204, SEDOL BSNMNQ5,
weight 0.00751, sector `-`, the same 6658074 shares). After
`ebf/spy._drop_non_equity` removes its two known non-equity rows (the US DOLLAR
cash line and the TPG contingent-value-right line), the file is **504 equity
rows**, which is the count the run requested: the timezone prewarm logged
**"503 resolved, 1 unresolved, of 504 requested"**, and a warrant line has no
timezone row — which is the one unresolved ticker.

**Absence from the previous evening's list cannot be re-fetched.** SSGA serves
one file at one URL and overwrites it daily, so the as-of 12-Oct file that the
2026-10-13 run read is gone (the Wayback Machine holds no snapshot of it). What
can be shown:

- the two archived files we do hold, `spy_holdings_2026-09-18` and
  `spy_holdings_2026-09-21`, carry **503** equity rows each, contain no ticker
  with a `/` in it at all, and carry the issuer under its pre-rename symbol
  **PSKY**;
- the file tonight's run read carries **504** equity rows, and the one extra row
  is the warrant;
- the run's own prewarm line (503 of 504) matches this list row for row.

Read together with the incident log's 404 for `SKYD/WS` and no 404 for anything
else, that is the whole of the available evidence: the 503-name list of the
earlier evenings became a 504-name list by adding a zero-weight warrant line, and
tonight was the first evening to price it.

### The reproduction, read-only, against the vendor

With `yfinance 1.7.0` / `pandas 3.0.5`:

| call | `yf.download` returns |
|---|---|
| `['SKYD/WS']` | a DataFrame with **0 rows** and only **6** columns — `Open, High, Low, Close, Adj Close, Volume` |
| `['AAPL']` | 7 rows × **8** columns, the 8th and 7th being `Dividends` and `Stock Splits` |

The action columns come with the rows: a symbol the vendor answered nothing for
arrives without `Dividends` and `Stock Splits`. `wide_to_long` then did
`long_df[FIELDS]` on a frame that has only the six price fields, and raised:

```
KeyError: "['dividend', 'split_factor'] not in index"
```

The failing call is the retry, not the bulk pass. The bulk pass asked the vendor
about all 504 names at once, the stack produced `SKYD/WS` rows with no prices
(because the other 503 names did have rows, the frame does carry the action
columns), `prices.missing_tickers` correctly found no usable close on the session
being priced, and `retry_missing_closes` asked the vendor about that one name
alone single-threaded — where the six-column, zero-row frame came back and the
selection raised. Before the fix, `prices.download_prices(['SKYD/WS'], …)` raises
the same `KeyError`; after it, it returns a `(0, 8)` frame with all eight
`FIELDS` columns and `['AAPL']` is unchanged at `(7, 8)`.

### Every other place that could hit it

Only one place indexes `FIELDS`: `efb/prices.wide_to_long`. Every other reader of
`dividend` / `split_factor` — `efb/hygiene.py`, `efb/prices.audit_adjusted_close`,
`efb/evaluate.py`, the `e11_prices` `InputSpec` in `live/appendix.py`, and
`live/corporate_actions.py` — reads the long frame or the stored artifact, which
now always carries all eight columns. `download_prices` had one more empty case:
an empty ticker list is refused by yfinance itself with
`ValueError: No objects to concatenate`, which is a crash in the fetch rather
than a frame with nothing in it, so that is answered too.

### Would tomorrow have failed the same way?

Yes, if nothing changed: tomorrow's file will almost certainly still carry
`SKYD/WS` (a warrant line with weight 0.0 that SSGA has already published once),
so the retry would ask for it alone again and raise the same `KeyError` before
sizing. That is why this is a fix and not a skip: the failure is in the reader,
not in the name.

## Step 2: the fix

**`efb/prices.wide_to_long`** reindexes `FIELDS` in instead of selecting them:

```python
long_df = long_df.reindex(columns=FIELDS).sort_index()   # was long_df[FIELDS]
```

An empty or partial answer is now a correctly shaped frame — empty, or only the
tickers that came back, with the fields the vendor omitted as NaN and the column
order always `FIELDS`. A missing column can no longer be a `KeyError`.

**`efb/prices.download_prices`** returns that same frame for an empty ticker list
instead of letting yfinance raise, through a new `prices.empty_long_frame()`.

**`live/extend.retry_missing_closes`** leaves a ticker that still has no data as
missing (a zero-row retry frame is a valid answer, and
`prices.missing_tickers` already reports every requested name as missing from
it) and logs each one by name:

```
live.extend: no prices from the vendor: SKYD/WS
```

The guard is applied at every place Step 1 found — which is the one selection in
`wide_to_long` plus the empty-list case in `download_prices`.

**No symbol is filtered by pattern.** Nothing drops a ticker because it contains
`/WS`; see the proposal at the end.

### What happens to `SKYD/WS` downstream with no prices

It lands in the proposal's existing excluded list and nowhere else:

- `build_proposal` computes `excluded = [t for t in spy_tickers if t not in
  wide_names]`, the universe members the frozen risk model cannot measure.
  `SKYD/WS` is in the SPY archive and not in the model, so it is in `excluded`.
- It is **not** a kept name, so the "dropped for no price" rule never sees it:
  `n_dropped_no_price` is 0 and `dropped_no_price` is empty.
- It is not in the kept book, so it cannot be sized, quantized or ordered.
- `evening_job.universe_without_prices()` returns an empty list: it asks which
  archive members have no *rows* for the session, and `SKYD/WS` does carry rows —
  eight of them, all NaN — so it is not in that report either.

## What tomorrow's 22:30 run should do

Tomorrow's run fetches a fresh holdings file (as of 2026-10-14), which will
almost certainly still list `SKYD/WS` at weight 0.0. With this fix, the run:

1. warms the timezone cache and logs `504 requested` with one unresolved;
2. gets 404 from the vendor for `SKYD/WS`, retries it once single-threaded, logs
   **`no prices from the vendor: SKYD/WS`**, and appends the sessions for the
   other 503 names;
3. carries `SKYD/WS` into the proposal's `excluded` list and counts it in
   `n_excluded`; it is never sized, never quantized and never ordered;
4. sizes and prices the rest of the book normally.

So the run is expected to complete. Two things to look for in its log, in that
order: the single `no prices from the vendor: SKYD/WS` line is normal and is the
name being handled, while the summary line naming *many* names missing on the
close is the vendor being down and is the run's own signal that tonight's fetch
broke.

**One observation the fix does not address.** `SKYD` — the equity line — is also
in `excluded` (`['DD', 'SKYD', 'SKYD/WS', 'TWLO', 'VYLR']`), because the frozen
risk model still carries this issuer's pre-rename symbol `PSKY`, so the model
cannot measure the equity either. That is a separate, pre-existing gap (the
`fix-symbol-resolution` branch is where it belongs), it is present identically on
`origin/main`, and the fix neither causes nor worsens it. It does mean the book
is one name narrower than the index until the rename is carried through; it is
worth its own evening.

**A pattern filter, proposed and not applied.** The instruction was not to filter
symbols by pattern unless the shape fix was not enough, and it is enough. If one
is wanted later, the right place is `efb/spy._drop_non_equity` — the function that
already drops the cash line and the contingent-value-right line explicitly and by
name, logging the reason — so a `/WS` warrant line would be dropped there, next to
the rows it resembles, with the same visible reason and no change to the model or
the archive. A zero-weight warrant row is arguably more useful kept and reported
than dropped, which is why this document stops at proposing it.
